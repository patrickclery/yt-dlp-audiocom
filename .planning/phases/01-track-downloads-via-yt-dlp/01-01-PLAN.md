## Phase Goal

**As a** yt-dlp user, **I want to** run yt-dlp with this repo's plugin on an audio.com track URL, **so that** I get an mp3 or m4a file with correct metadata, without impersonation.

_real_extract(url) follows D-05 exactly:
1. Take the user and slug groups from self._match_valid_url(url).
2. canonical = self._canonical_url(user, slug).
3. oembed = self._download_json(f'{self._API_BASE}/oembed', slug, 'Downloading oEmbed JSON', query={'url': canonical}).
4. track_id = self._search_regex(r'/embed/audio/(\d+)', traverse_obj(oembed, ('iframe_url', {str})) or '', 'track id').
5. data = self._download_json(f'{self._API_BASE}/audio/{track_id}', track_id, 'Downloading track JSON').
6. If traverse_obj(data, ('id', {str})) is non-empty and differs from track_id, raise ExtractorError with a message naming both ids.
7. Build formats from every transcodings entry whose url passes url_or_none. Each format has url, format_id equal to ext, ext equal to the entry's format string (never parse the signed URL path, per D-06), vcodec 'none', acodec from codec, and abr from bit_rate via float_or_none(x, 1000).
8. If no formats result, raise ExtractorError('No playable transcodings found', expected=True).
9. Return id track_id, display_id slug, title from the data title, and formats.

Never fetch the HTML track page. Never pass a browser-fingerprinting keyword argument to any request helper. Never read the API's original-upload file list (D-13, Phase 2). Use self.to_screen or self.write_debug for messages, never bare print.
